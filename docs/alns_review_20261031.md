# ALNS 检查与修复（2026-10-31）

## 发现的问题

1. `elite_limit`、`inner_iterations` 和 `stagnation_limit` 原来只检查是否小于 1，小数、NaN、无穷大和布尔值可能通过。小数迭代数随后会在 `range()` 中报错；NaN 的比较也可能使预算或停止条件失效。现要求三个参数为正整数，支持 NumPy 整数，并在错误消息中注明参数名。
2. 参数调度会修改求解器的交叉率、变异率，但重新运行同一求解器时没有还原。相同种子重复运行的第 0 代记录因此不同。现每次初始化恢复构造时的概率，同时重置权重、得分、次数与代数。原问题主要影响初始日志；不应据此推断此前独立运行的优化结果无效。

## 检查范围

- 随机移除、按边际航程移除，以及贪婪插入、随机插入的四种组合。
- 客户恰好覆盖一次、父代不被修改、载重、无人机数量、含返航的航程和任务时长。
- 精英触发与全量触发、全不可行种群的跳过处理。
- 权重反馈、退火接受、额外评价次数、环境选择、固定种子复现。
- 不同预算的输入校验，以及同一求解器重复运行的完整历史一致性。

目前未在以上正常输入流程中发现导致漏送、重复配送或违反硬约束的缺陷。回归测试位于 `tests/test_alns.py`，既有综合测试位于 `tests/test_drone.py`。

## 实现上的限制

修复算子用增量距离选插入位置，最终仍通过距离最优 split 解码。重新解码可能改变临时修复路径的分段，这是现有排列编码的设计；不能将其解释为直接对完整三目标做最优插入。固定代数下 ALNS 还会增加评价预算，不能由此声称严格等算力优势。此次没有改变这些实验约定，也没有用新结果覆盖旧实验。
