# Solomon 数据精度与校验

## 来源

项目使用 PyVRP/Instances 的 VRPTW/Solomon 目录，包含 56 个算例的 `.vrp` 和 `.sol` 共 112 个文件。原始文件 SHA-256 和上游提交记录在 `data/raw/solomon/PROVENANCE.json`。

```bash
python scripts/fetch_solomon.py --verify
python scripts/run_preprocess.py --quiet
```

## 两种距离口径

本项目原始 VRPTW 基线使用精确欧氏距离。上游参考解的声明成本使用每条边的欧氏长度乘 10、向下取整再除以 10。必须先逐边处理，再累计路径和车队成本，不能只截断最终总和。

| 算例 | 声明成本 | 逐边截断一位小数 | 精确欧氏距离 |
|---|---:|---:|---:|
| C101 | 827.3 | 827.3 | 828.9369 |
| R101 | 1637.7 | 1637.7 | 1642.8769 |
| RC101 | 1619.8 | 1619.8 | 1623.5571 |

已逐一核验全部 56 个参考文件，成本均与逐边截断结果一致，路径也在该精度下满足时间窗和载重。原说明把成本差认定为参考路径较差或文件缺陷，没有事实依据，现已修正。

## 校验规则

节点数、客户覆盖、唯一服务、车辆上限、上游距离下的声明成本和路径可行性均按错误级别检查，任一失败会让预处理返回非零退出码。

精确欧氏距离下另做严格可行性检查。56 个参考解中有 8 个出现不足 0.4 个时间单位的时间窗超出；这是更换距离精度后的模型差异，作为提示记录，并不说明上游参考文件在自身口径下不可行。0.5 容差仅用于历史精确欧氏诊断，求解器仍使用 1e-9。

当前预处理报告包含 1176 项全算例检查，0 个错误和 8 个精度差异提示；三个 10 客户子算例各有 15 项检查。子算例检查独立列出，不计入 1176。

`manifest.csv` 的 `ref_cost_published` 为上游声明值，`ref_cost_recomputed` 为精确欧氏重算值。`ref_cost_delta` 只是两种精度的差，不代表算法改进。

## 无人机场景

三目标实验取 C101、R101、RC101 的前 25 个客户，保留原始坐标和需求等量纲。河流带、桥位、风险源和紧急客户由 `configs/` 明确给出。它们是可复现的合成场景，不是实测地理或飞行安全数据。该模型使用真实折线路径的精确欧氏长度，不引用上游 VRPTW 的声明成本作为最优对照。
